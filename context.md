**Current version:** 1.1.0 (root manifest; every workspace manifest carries the same number)
**Last updated:** 2026-09-25 (v1.1.0 released)
**Owner:** harryx2011@gmail.com
**Repo:** https://github.com/harryx2011-boop/sparky (public, MIT, default branch `main`)
**Site:** https://sparky-labs.vercel.app (Vercel project `sparky-labs`, production branch `main`, auto-deploys on push; config in `vercel.json`, upload filter `.vercelignore`)
**Installer:** `Sparky-Setup.exe` on GitHub Releases, built by `.github/workflows/release.yml` when a `v*` tag is pushed. The site's download button points at `releases/latest/download/Sparky-Setup.exe`, so the artifact name is fixed (no version in it) on purpose.

## What it is

A free Windows desktop app (Electron) that converts files (video, audio, images, documents, archives, and shrinking a file in its own format) and downloads from links (YouTube and the other yt-dlp sites, playlists, up to 4K), all on the user's PC. Also a suite chapter on ElixirLabs (`D:\ElixirLabs`, chapter 05).

## Layout

- `apps/desktop` — Electron app. `src/main` hosts the engine from `packages/engine`, `src/preload` the bridge (`window.sparky`), `src/renderer` the React UI. `npm run dev:ui -w @sparky/desktop` runs the UI in a browser against `lib/mock.ts`.
- `apps/web` — landing site (Vite + React + Motion).
- `packages/engine` — the job engine (no Electron imports, tested under Node): the op registry in `src/ops/` (`OPS`, one module per op; `convert` and `download` today), queue, tool runners, output planning (`output.ts`), SQLite history and settings. Its explicit `Engine` interface is the one surface the app, and later the HTTP API, MCP server and CLI, call. Details under Decisions.
- `packages/core` — pure logic and every user-facing label/error string (`levels.ts`, `display.ts`, `errors.ts`, `ytdlp.ts`).
- `packages/ui` — shared visuals (Performance bars, Compression slider, logo mark).
- `scripts/` — `fetch-tools.mjs` (bundled binaries into `apps/desktop/resources/bin`, gitignored), `fetch-fonts.mjs` (Satoshi, gitignored), `make-icons.mjs` (all icons + NSIS sidebar/header BMPs from one SVG).

## Decisions (settled 2026-09-24)

- **Logo:** dark tile `#0A0A0A` with a `#2A2A2A` hairline and a white `#EDEDED` bolt (inverted from the original light tile). Source of truth: `scripts/make-icons.mjs`.
- **Dark mode is the app default.** The site is dark only.
- **Lime is the one accent**, shared with the ElixirLabs suite, defined once in `packages/ui/src/styles.css`: dark `--lime #b6f04a` / `--lime-foreground #0a0a0a` (14.7:1 on `#0a0a0a`), light `--lime #62990f` / `--lime-foreground #111111` (3.3:1 on `#fafafa` for rings and fills, 5.5:1 for dark text on it; `#7fc21c` fails at 2.1:1). `--ring` is the lime. Homes: the primary action (site "Download for Windows", app default `Button`), live/on states (switch on, `.sp-running` progress, the 3px lime rail on the active sidebar item and selected Performance level, the queue badge and dock dot), the focus ring, `::selection`, and the drag-over state (lime dashed border + `bg-lime/8`). Never body text, borders, backgrounds or gradients; Performance bars, success, warning and destructive keep their own colours. No narration captions, typewriter lines or step tickers on demos (`ui-anti-vibe.md`).
- **Plain language everywhere.** No cores, CPU/GPU, encoder, codec, bitrate, yt-dlp or FFmpeg in user-facing copy outside the credits line. Harry's `~/.claude/reference/ui-anti-vibe.md` applies: no text or pill above headings, no pill/chip/tip-card rows, no copy over an unmasked busy background.
- **Compression's first stop is "Lossless" (original quality export).**
- **Batch conversion is on by default**; the old "Jobs at once" 1–8 picker is gone. The rule is `batchConcurrency(level, cores, batch)` in `packages/core/src/levels.ts`: off or Low 1, Normal 2, Max half the processor threads clamped to 2–4. The engine re-applies it on every settings change; an old stored `concurrency` migrates to `batch` (> 1 means on) in `store.ts`.
- **Sites and brand marks:** one registry per site in `packages/core/src/sites.ts` (`SITES`, `siteFor(url)`), and its mark table in `packages/ui/src/brands.tsx` (`BRAND_MARKS`, `BrandMark`, `LinkMark`, official Simple Icons paths and hex, inline so they paint offline; near-black brands such as X and TikTok take the text colour). Add a site: one row in each.
- **Default output root is `Downloads\Sparky`** (`apps/desktop/src/main/index.ts`, `defaultRoot`), used for both downloads and conversions on a fresh install; an existing user's own choice in the settings DB is untouched.
- **Dropping a folder** adds the files inside it (one level, hidden files skipped): `expandFolders` in `packages/engine/src/convert.ts`. Files dragged anywhere over the window go to Convert via `renderer/src/components/FileDropOverlay.tsx`.
- **Type:** Satoshi, then a `"Satoshi Fallback"` face (`packages/ui/src/styles.css`) that maps local Segoe UI Variable / Segoe UI / Helvetica Neue / Arial onto Satoshi's vertical metrics (ascent 101%, descent 24%, gap 10%), one face per weight bucket so static Bold files still resolve, so the fallback lays out like the real font. Headlines are fluid: hero and Get `clamp(40px, 2.6vw + 26px, 64px)`, section h2 `clamp(36px, 2vw + 24px, 52px)`, leading 1.04. `SplitText` masks each word with `pb-[0.25em] -mb-[0.25em]` so the rise-in clip never cuts descenders (the old 0.08em cut Segoe's `y` and `g` flat when Satoshi was missing, 2026-09-24).
- **Fonts on Vercel:** `scripts/fetch-fonts.mjs` chmods 7-Zip on non-Windows; npm drops the execute bit and the Vercel build printed `7za EACCES`, so every deploy before 2026-09-24 shipped without Satoshi. If the Fontshare fetch fails, the build still succeeds (`;` in `vercel.json`) on the fallback face.
- **Site background:** `apps/web/src/components/GridCells.tsx` (fixed, `-z-10`, ported from Helix); the hero paints calm ground over it under the headline.
- **First paint is dark:** `renderer/index.html` starts with `class="dark"`, `useTheme` only toggles once settings arrive, and `main/index.ts` picks the window `backgroundColor` from the saved theme.
- **FFmpeg is the oldest BtbN release branch, never master.** Master and 9.0 need NVIDIA driver 610+ (NVENC API 13.1); 8.1 works on 591-era drivers. Checked on an RTX 2070 SUPER, driver 591.86.
- **Installer:** NSIS assisted (not one-click), per-user, directory choice, licence page, desktop + Start menu shortcuts, runs Sparky at finish. Unsigned: Windows SmartScreen warns on first run until the app is code-signed (needs a certificate; Harry's call).
- **Engine and ops (2026-09-25, 1.1 Phase 1):** the engine lives in `packages/engine`; every capability is an op (`src/ops/<op>.ts` + one line in `OPS`), and the queue runs a job by `opById(job.op)`. `Job` gained `op`, `args` (validated input, including `out`) and `restartsOnResume` (from `Op.resumable`); `kind` is the app bucket `convert | download | tool`. `startOp` validates with zod/v4 and throws `OpInputError { code, message, field }` before queueing; `runOp` settles on done/failed/canceled/paused. `out` is added by the engine to every op input: a folder when it exists, ends in a separator or has no extension, else the file itself; it wins over originals "replace" and the output root. Final names are reserved on disk (`wx`) so two processes never pick the same "clip (2).mp4"; names compare case-insensitively on Windows, and an `out` naming the source itself swaps in place (the original is set aside, never the result trashed). `out` and each op's `paths` fields are made absolute at validation, so reruns and other processes see the same files. A missing folder whose name has a dot reads as a file; end it with a separator. History migrates by `PRAGMA user_version` (v1: `op`, `args` columns; old rows read `op ?? kind` and rebuild args from the convert/download block). Scratch files go to `<temp>/Sparky/<pid>`; startup sweeps only dead pids. `EngineHost.printToPdf`/`trash` are optional; without them the `print`/`trash` capabilities are missing and the ops that need them refuse up front. The app declares `turndown` (and the native modules) at the engine's ranges so nothing it leaves external goes missing in the installer; `deps.test.ts` checks it. `defaultPaths()` gives a CLI the app's data folder, temp root and tool folders. Data documents (csv, xlsx, json, xml, plus pdf to html) convert through the `document` engine kind in `engineFor` (`packages/engine/src/document/`); every pair that worked before 1.1 keeps its old engine. Old `.xls` is accepted and only becomes PDF, only through LibreOffice.

- **Tools and ops (2026-09-25, 1.1 Phase 2):** twenty ops beyond `convert` and `download`, each one file under `packages/engine/src/{pdf,media,image,ocr}/` registered through `src/ops/{pdf,media,image,ocr}.ts`, with every label, field title and message in `packages/core/src/ops-text/<module>.ts`. PDF: `pdf.from_images`, `pdf.to_images` (pdfjs + `@napi-rs/canvas`, `src/pdf/raster.ts` is the shared rasterizer), `pdf.merge`, `pdf.split`, `pdf.rotate`, `pdf.remove_pages`, `pdf.extract_pages`, `pdf.extract_images`, `pdf.flatten`, and three that need Ghostscript: `pdf.compress`, `pdf.protect`, `pdf.unlock`. Page specs (`packages/core/src/pages.ts`) take "1-3,5,8-", `odd`, `even`, `all`, `last`. Media (native ffmpeg, convert's own encoder plan, GPU only on Max): `media.edit` (trim, crop, rotate, flip, resize, fps, strip audio, volume, fade, reverse, speed), `media.compress` (Email/Discord/Web/Archive or a size in MB; two-pass on the processor, one pass on the card and redone on the processor when the card lands over target), `media.thumbs` (poster, sprite, preview), `media.gif`. Images (sharp; sources read as bytes so libvips never holds a user's file open): `image.edit`, `image.ico` (hand-written multi-size ICO with PNG frames), `image.gif` (sharp's animated join). `ocr` (tesseract.js 7; English data bundled by `fetch-tools` into `resources/bin/tessdata`, other languages fetched on demand into `<data>/tessdata`; txt, searchable PDF or both; images only for now). TIFF is an image output. Office inputs (doc, rtf, odt, ods, ppt, pptx, odp, xls) convert only through LibreOffice when it is installed; the Convert page hides a target no chosen file can reach and says what is missing. **Secrets:** an op lists `secret` fields (the PDF passwords); they never enter the job, the queue snapshot or History (a rerun asks again), and Ghostscript reads them from a `@argfile` in the process's temp folder, never its command line. Ghostscript 10 exits 0 when it cannot open the input (wrong password included) and writes an empty PDF, so every Ghostscript call goes through `runGhostscript`, which reads stderr; `%` in an output path is escaped; passwords are Latin-1 hex so pdf.js and Acrobat open the file. **Tools page** (`renderer/src/pages/ToolsPage.tsx`, Ctrl+3): the form for any op is generated from its input JSON schema (`title`/`description` from each field's `.meta`), required fields first, optional under "More options", `out` as a "Save to" folder row; unavailable ops are muted with one line naming the missing program. IPC: `ops:list`, `ops:targets`, `ops:start`. Ports: site dev 4600, renderer `dev:ui` 4601.

- **Agent surfaces (2026-09-25, 1.1 Phase 3):** three ways in, all generated from the op registry. **HTTP API** (`packages/engine/src/http/`, Fastify, bound to 127.0.0.1 only, port 8600 or `SPARKY_API_PORT`): the app hosts it while open (`host: 'app'`), `sparky serve` hosts it without the app. Bearer token in `%APPDATA%\Sparky\api-token` (64 hex chars, created atomically with a temp file + link so two processes never disagree; mode 0600); every route needs it except `GET /v1/hello?nonce=`, which answers `hmac-sha256(token, nonce)` so a client can prove it is talking to Sparky before it sends the token. Routes: `/v1/health`, `/v1/ops`, `/v1/formats`, `POST /v1/targets`, `POST /v1/jobs {op,args,wait,timeoutMs}` (200 after settle, 202 with `wait:false`; a client disconnect never cancels), `GET|DELETE /v1/jobs/:id`. Errors `{ error, message, field?, requestId }` with 400/401/404/422/500, never a stack. Settings gets `api:info` and `api:revealToken` (opens the folder; the clipboard is never used because Windows keeps clipboard history). **CLI** (`packages/cli`, npm `@sparky-labs/cli`, bin `sparky`; esbuild single-file bundle with the native modules external): `sparky convert|download|ocr|pdf <tool>|media <tool>|image <tool>` from the registry, plus `ops`, `formats`, `jobs`, `cancel`, `serve`, `mcp`, `init`, `setup`. It talks to the running app when the hello proof checks out (jobs show in the Queue), else runs the engine in-process. Secret fields never go on the command line: `--password -` (stdin), `SPARKY_<FIELD>`, or a hidden prompt. Exit codes 0/1/2/3/130. `sparky init --client claude-code|cursor|codex|windsurf` upserts an MCP entry (`cmd /c sparky mcp` on Windows) without touching other entries, keeping BOM, mode and symlinks. **MCP over stdio** (`sparky mcp`): one tool per op named `sparky_<id with dots as underscores>` plus `sparky_list_ops`, `sparky_list_formats`, `sparky_get_job`, `sparky_cancel_job`; text results with a JSON block of jobs, never bytes, secrets blanked. **Installer:** the CLI ships inside the app with no second Node: `resources\cli\sparky.cmd` and an extensionless `sparky` (for Git Bash) run `Sparky.exe` with `ELECTRON_RUN_AS_NODE=1`, `NODE_PATH` at the app's node_modules, `SPARKY_BIN_DIR`, and the bundle in `resources\cli\lib\` (kept out of the PATH folder because `.JS` is in PATHEXT). `build/installer.nsh` adds that folder to the user PATH (HKCU, REG_EXPAND_SZ, no duplicates) and removes exactly that entry on uninstall; an update stops running `sparky mcp` processes, and agents reconnect. `scripts/stage-cli.mjs` builds and stages the bundle inside `npm run package`. `sparky setup` fetches the tools into `%APPDATA%\Sparky\bin` for npm installs (`scripts/fetch-tools.mjs` exports `fetchTools`). The npm scope `sparky-labs` does not exist yet; publishing is a manual step. Node floor for the npm CLI is 22.12 (`require()` of ESM). **OCR** now takes PDFs too (pages rendered through `src/pdf/raster.ts`, text joined with a form feed, searchable PDF merged per page). Ports: site dev 4600, renderer `dev:ui` 4601, API 8600.
- **Compression slider (2026-09-25):** a 28px pill with a flat `--lime` fill, two slow sheen bands and eight drifting sparks (motion only, no hue gradient; `.sp-flow` in `packages/ui/src/styles.css`, `FlowingTrack.tsx`), a large round thumb; reduced motion leaves the plain fill. This is the one other lime fill besides the homes listed above.

- **File icons and Settings (2026-09-25, 1.1 Phase 4):** file rows, the format picker, Queue, dock and History show the icon Windows itself assigns to the type (`apps/desktop/src/main/icons.ts`: `app.getFileIcon` on a probe path, cached per extension, `null` when the icon is blank or matches the one Windows gives an unknown extension), falling back to a vendored subset of the vscode-icons pack (MIT, 21 SVGs pinned by commit in `packages/ui/src/file-icons/`, a self-contained folder other apps can copy; five low-contrast fills take the text colour in dark mode, listed in its LICENSE). Queue and History rows show source → target icons with a small done/failed badge instead of the old status tile; tool jobs get a wrench, downloads keep their mark; the sidebar keeps lucide. **Settings:** the "Built-in tools" group became **Diagnostics** (tool status, downloader update) above About; an **Agents** group after Defaults shows the local API status and port, a "Show file" button for the token file, and one row per agent client (Claude Code, Cursor, Codex, Windsurf) with an "Add to …" button; the harness registry lives in `packages/engine/src/agents/harnesses.ts` and the CLI re-exports it. The app writes `cmd /c sparky mcp` when the shim is on PATH, else the shim's full path. **Site:** "More than converting" lists the tools from `apps/web/src/data/ops.json`, generated from the registry by `scripts/gen-site-ops.mjs` (`npm run gen:ops -w @sparky/web`; regenerate after adding an op), and "Your agents can use it too" carries the Claude Code line, two CLI lines and a PowerShell call; the nav shows section links from 1024px.

## Build and verify

- `npm install`, then `npm run fetch-tools` and `npm run fetch-fonts` (Windows).
- `npm run check` — typecheck, all tests, both builds. Set `SPARKY_TEST_BIN` to the absolute `D:/sparky/sparky/apps/desktop/resources/bin` so the engine tests run the real tools (otherwise they skip, and with `CI` set they throw instead); a relative path resolves against `packages/engine` and the suites fail with `spawn ffmpeg ENOENT`.
- `npm test`'s `pretest` rebuilds better-sqlite3 for Node; run `npm run app-deps -w @sparky/desktop` before launching Electron again.
- `npm run package:win` builds `apps/desktop/release/Sparky-Setup.exe` + `latest.yml`.
- **VS Code terminals export `ELECTRON_RUN_AS_NODE=1`**, which makes Electron run as plain Node (`electron.app` undefined). Clear it before `npm run dev:app` or launching the exe.
- Electron is pinned to an exact version (`apps/desktop/package.json`): electron-builder can't resolve a range when npm hoists Electron to the workspace root.
